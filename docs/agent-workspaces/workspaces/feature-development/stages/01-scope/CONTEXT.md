# Define feature acceptance

## Inputs
- Explicit user request
- Existing capabilities and product boundaries

## Procedure
1. Define the observable behavior, constraints and non-goals.
2. Identify offline, accessibility, data and permissions requirements.
3. Record any user approval required for consequential effects.

## Outputs
- feature-contract.md: concrete acceptance criteria, constraints and failure modes

## Acceptance
- Scope is testable and does not silently rewrite existing behavior.
