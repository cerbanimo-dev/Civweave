# Civweave Content Creation Provenance Contract v1

Status: proposed shared contract for the instrumented creation stack.

## Purpose

Civweave records trustworthy, privacy-preserving evidence about how text, audio, and video artifacts were created without turning creation into pervasive oversight. The existing `CivweaveContentProvenanceV1` capability remains the artifact-origin authority. Creation tools, AI systems, importers, Guild audit jobs, and export adapters are callers or subscribers of that owner.

## Creator Suite packaging boundary

The text/audio/video authoring environment is an **optional, separately downloadable Creator Suite**, not part of Civweave's ordinary offline core.

- Package scope: `/creator-suite/`
- Package manifest: `/creator-suite/package-v1.json`
- Installed entry: `/creator-suite/index.html`
- Service-worker scope: `/creator-suite/`
- The ordinary Civweave offline package must not implicitly pull Creator Suite editor engines, media-processing assets, or third-party editor dependencies into the core install.
- The Creator Suite may call the canonical provenance, Passport identity, mesh, Guild, and AI capability APIs as explicitly declared shared dependencies.
- AI systems and human UI operate through the same Creator Suite command/editing adapters when the suite is installed. Core Civweave must degrade cleanly when the optional suite is absent.

## Trust boundary

The platform may assert only what its signed event history proves.

- `human-authored`: creation history contains human-controlled creation operations and no generative AI origin event for the artifact's originating content.
- `ai-generated`: the originating content includes a Civweave AI generation event or carries trusted imported AI-generation provenance.
- `deterministic-generated`: generated by non-AI deterministic machinery.
- `unknown`: imported or legacy content without sufficient trusted provenance.

Human validation is additive. Review never rewrites creation origin.

## Canonical API

Owner: `public/app/content-provenance-v1.js`

Global: `globalThis.CivweaveContentProvenanceV1`

The owner must preserve the existing v1 artifact-origin API and add the following creation-session API without requiring network access:

- `createSession(details)` -> local creation session
- `recordEvent(session, event)` -> Promise resolving to a new session state containing one appended hash-chained event
- `verifySession(session)` -> Promise resolving to structural/hash-chain verification results
- `summarizeSession(session)` -> deterministic provenance summary
- `finalizeSession(session, artifact)` -> Promise resolving to a creation receipt and artifact provenance
- `makePacket(session, options)` -> Promise resolving to a compact packet envelope suitable for encryption/storage/transport

The session/event/packet schema names are fixed for v1:

- `civweave.creation-session.v1`
- `civweave.creation-event.v1`
- `civweave.creation-packet.v1`
- `civweave.creation-receipt.v1`

## Actor classes

Each recorded event carries exactly one actor class:

- `human`
- `civweave-ai`
- `deterministic`
- `external`

AI actors should also carry provider/model/request identifiers when available. External imports never become human-authored merely because a human imported them.

## Event classes

The event model is media-neutral. Adapters map concrete editor operations into these semantic classes:

- session: `session.created`, `session.checkpoint`, `session.finalized`
- text: `text.insert`, `text.delete`, `text.replace`, `text.format`
- media: `media.import`, `media.remove`
- audio: `audio.record`, `audio.cut`, `audio.move`, `audio.gain`, `audio.effect`
- video: `video.record`, `video.add-clip`, `video.trim`, `video.move`, `video.transition`, `video.effect`
- generation: `ai.generate`, `ai.transform`
- transfer: `external.paste`, `external.import`
- export: `artifact.export`

Adapters may add namespaced event types but must not change actor semantics or origin classification.

## Hash chain

Every event has:

- monotonically increasing `seq`
- timestamp
- actor envelope
- semantic event type
- sanitized operation metadata
- `previousHash`
- `hash`

`hash` is SHA-256 over canonical serialized event data excluding the `hash` field itself. The first event uses an empty `previousHash`.

The session head hash is the final event hash. Editing an earlier event, removing an event, reordering events, or changing actor metadata must invalidate verification.

## Privacy boundary

Raw creative content does not belong in the public ledger by default. Event payloads should contain operation metadata and content digests rather than full document/audio/video contents unless a specific local-only adapter requires more detail.

Detailed creation packets remain local or encrypted for explicitly authorized audit/recovery. Public/shared receipts contain summaries and commitments, not private drafts.

## Packet boundary

A packet contains:

- session identity and schema
- media/artifact type
- event count
- head hash
- deterministic summary
- compact event records or event chunk commitments
- packet content hash

Encryption, compression, key distribution, Guild storage, mesh transport, SCITT-style receipts, and C2PA embedding are adapters around this packet contract. They must not redefine origin.

## Audit semantics

A Guild/model/human review answers: `what provenance claims are verifiable and what anomalies exist?`

It must not claim that untracked content is definitively human- or AI-generated. Unknown provenance remains unknown unless trusted origin evidence is added.

Recommended review outcomes:

- `verified`
- `verified-with-ai`
- `unknown-origin`
- `broken-chain`
- `anomalous`
- `needs-human-review`

## Parallel implementation rule

Once this contract is merged, text, audio, video, AI tool adapters, packet crypto, mesh transport, Guild sampling, tribunal UI, ledger receipts, C2PA, storage, export UX, import verification, and adversarial testing may be implemented independently. They communicate only through this contract and the existing artifact-origin metadata contract.
