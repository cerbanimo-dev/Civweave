# Quest pathway map

`public/app/shared/quest-pathway-map-v1.js` and CSS present a saved Weaveling Quest as four subsystem regions with connected beat trails. A generated response displays the map immediately using the current saved Quest. Its transcript snapshot is an identifier hint, never authority to restore deleted work. Ordinary transcript updates preserve the unchanged map and streamed answer DOM.

`CivweaveQuestPathwayMapV1.render(plan, options)` returns bounded inert markup: at most 12 paths/layers and 96 beats. All four subsystems remain visible, even when a goal needs no path there. Unrecognized subsystems remain visible in an unassigned region. Saved accepted/completed labels and member-reported publication labels are distinct. Declared dependencies resolve only against unique visible saved identifiers; unknown, ambiguous, and incomplete references remain locked. Ordered trails are explicitly labelled as order, not invented dependencies.

`bind(host, callback)` supplies only the allowlisted `inspect`, `edit`, `open-native`, and `submit-guild` actions with exact Quest/path/step identifiers and indexes. It creates no stores, model calls, proof, activation, votes, publications, or rewards. Buttons are semantic keyboard controls with 44px mobile targets; Lud removes decorative symbols and reduced motion disables effects.

The immediate thread diagram uses the canonical subsystem colors: Living School green `#9acb70`, Cerbanimo purple `#bb79ff`, FellowFare amber `#f5b446`, and Anarchadia rose `#ff3d96`. Curved solid dependency threads transition between the two subsystem colors at a handoff. A background-colored underlay separates crossings. Dotted trails indicate beat order only. Every node delegates inspection to the same review owner; the full semantic beat list and native controls remain in expandable path details. The diagram scrolls within a bounded region on small screens and never expands the page width.

`project(plan)` produces the bounded node/edge layout without DOM writes. Duplicate or missing references do not produce guessed connections. Declared cycles are visibly flagged and remain locked; prerequisites determine the layout before visual beat order. At most192 dependency connectors are drawn, with any omissions declared and all bounded reference details retained. `canOpenPath(plan, pathId)` supplies the same dependency availability check to canonical navigation. The action handler rereads the saved Quest and checks this result instead of trusting an enabled button.

One theme parameter changes presentation without changing ownership or colors: Civweave's weave chart, Living School's forest notebook, Cerbanimo's workshop blueprint, FellowFare's trading ledger, and Anarchadia's civic constellation. The host subsystem supplies the default; a guide transcript explicitly supplies its current guide theme. Lud shows the complete semantic details directly. No model, timer, resize observer or animation loop is required to draw the map.

The canonical four-subsystem authoring shape declares its `pathOrder` as prerequisite order. Normalization now retains that meaning as exact saved path `dependsOn` identifiers plus `dependencyOrder` provenance. Arbitrary path arrays and Starling arrays do not acquire dependencies merely from their array order. Existing saved plans lacking dependency fields remain unknown; this renderer does not rewrite them. Explicit fork/join references can be displayed and published, although current four-slot model authoring still expresses its existing ordered chain. Both browser and server Guild privacy projections retain only bounded dependency identifiers, never dependency-object notes or evidence.

The canonical shared review owner's `handleMapAction` verifies the saved Quest and exact path before opening details or native controls. Edit currently opens the existing revision request workflow; a required note returns the saved plan to review without erasing its execution evidence. Direct node editing of titles, steps, or dependencies remains pending rather than exposing the old editor's independent activation/deletion controls.

Native navigation preserves both `weave` and `path`. Living School selects a matching activated routed path and pre-fills its existing controls without starting inference or replacing an existing curriculum. Every learning path remains separately selectable. Cerbanimo uses its canonical materialization owner. FellowFare and Anarchadia reject missing explicit IDs, unrelated stale handoffs, wrong subsystems, and stopped Quests. Anarchadia opens its existing Workbench. These remain the authoritative work and proof owners; the central map never marks a node complete.

The Guild tracker uses this same map renderer for published snapshots, clearly labels member-reported progress, and inspects the saved publication without importing it as a private Quest. An exact locally saved Quest may enter the existing submission composer through `openSubmission(id)` or Civweave's fixed persistent destination `nativePage=guild-quests&submitQuest=ID`. The route accepts only 1–180 identifier characters from `[A-Za-z0-9:_-]`. It can read/preload a named preview; only the existing explicit final submission action posts. Missing membership retains the login gate. Publication privacy, author authority, and revision checks remain in the existing Guild publication contract.
