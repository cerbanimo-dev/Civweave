# Runtime stability and AI validation v1.0.33

## Cerbanimo validation authority

Cerbanimo workers may submit evidence but cannot accept or reject their own work. A submitted work unit now enters independent AI validation through the shared configured generative provider.

The validator:

- evaluates the declared acceptance criteria against submitted proof
- treats proof as untrusted evidence, never as model instructions
- records criterion-level pass/fail reasons, provider, model, confidence, concerns, repair instructions, and request ID
- rejects deterministic, reflex, MiniLM, manual, or fallback output as independent validation
- leaves the work unit in review when no qualified provider is available
- requires all work units to pass independent validation before final quest validation

AI validation does not automatically mint rewards, publish work, spend funds, or create governance authority.

## Working guide lifecycle

The lazy guide loader now removes stale partially loaded script tags, times out incomplete loads, and can reset its promise after failure. The guide chat owns one listener set and permits only one in-flight request per realm. Closing and reopening a dialog does not create another hidden model call.

## FellowFare surface boundary

FellowFare no longer mounts the shared Cabinet Home opening card over its exchange application. The dedicated FellowFare page identifies itself explicitly, launches the mature local market and agreement ledger, and delegates guide access to Rook through the shared family shell.

## Working Campus models

The Working Campus includes a prefilled Gemini configuration and separate connection tests for Gemini and Antigravity. Antigravity testing verifies that the actual responding model is Antigravity; a standard Gemini fallback is reported as a failed Antigravity test rather than a false success.

API keys remain session-only unless the user deliberately changes the broader model-storage policy.

## Anarchadia startup

Anarchadia opens through its native Citizen Console without legacy Cabinet Home or Cabinet Surface overlays. Governance, workbench, and sovereignty bridges mount during a bounded startup window rather than observing the whole document indefinitely.

The local-sovereignty runtime validates and caps stored operations, quarantines malformed or unsafe legacy profiles, and only installs a DOM observer when an active safe profile genuinely requires dynamic reapplication.
