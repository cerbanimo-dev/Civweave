# Cabinet Interface Audit v1.0.29

## Result

The five supplied cabinet artworks are runtime interface shells, not mockups or decorative screenshots.

## Shared structure

- 5 systems
- 59 canonical rooms
- 117 canonical capabilities
- 17 golden-path steps
- identical room and capability IDs in Visual and Lite

## Cabinet projection

Each system declares:

- cabinet artwork payload parts;
- a calibrated rectangular projection region;
- visual motif and secondary accent;
- physical control order for system switching.

The Lite renderer reconstructs the selected cabinet, projects its room and capability interface into the declared screen, and keeps room navigation, capability details, native forms, and working-source tools inside that boundary.

## Native Civweave flow

The cabinet workstation contains native local controls for:

1. model route setup;
2. wish intake;
3. wish clarification;
4. skill posture and current level;
5. three-path weave generation;
6. weave review and revision;
7. explicit activation consent;
8. Passport sealing consent;
9. Acorns and Buttons display.

## Existing feature surfaces

Mature Living School, Cerbanimo, FellowFare, and Anarchadia tools remain reachable through an in-screen workspace. Source pages receive a system marker and a cabinet-world stylesheet so forms, controls, focus states, panels, tables, and typography visually belong to their parent system.

## Consent

The parity ledger continues to classify actions as `automatic`, `review`, or `explicit`. Weave activation and Passport sealing require affirmative user confirmation.

## Validation

`npm run check` passed with cabinet asset reconstruction, all source bridges, both renderer routes, legacy redirects, host metadata, and boot logging verified.
