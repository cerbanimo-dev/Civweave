CIVWEAVE GUILDKEEPER

Choose a local Anchor

A local Anchor gives this Guild another device-held copy of its identity and mesh state. Phones and tablets can act as opportunistic Pocket Anchors; desktops, Raspberry Pis, NAS devices, and home servers can run persistent Anchors.

These routes are complementary. A Pocket Anchor can travel with a Guildkeeper while a persistent Anchor stays awake at home or on site. Adding either route does not create a different Guild.

PERSISTENT ANCHOR

Desktop, Raspberry Pi, NAS, or home server

This machine supplies its own CPU, storage, memory, and network connection. It does not borrow compute from the Guild where you downloaded Civweave.

1. Install prerequisites and check Docker

Install Git and Docker Desktop/Engine with Docker Compose v2 on the machine that will stay near this Guild.

docker version
docker context ls

On Docker Desktop for Windows, docker version must show both Client and Server. Civweave's host image is Linux-based, so Docker Desktop must have its Linux container engine running before continuing.

2. Clone Civweave

git clone https://github.com/cerbanimo-dev/Civweave.git
cd Civweave
cp .env.federated.example .env.federated

Keep the data directory persistent. It contains this host's technical identity, signing material, federation trust, and retained relay state.

3. Start the persistent Guild host

docker compose --env-file .env.federated -f docker-compose.federated.yml up -d --build

Run the command as one line. It works in PowerShell as written; do not add Bash-style trailing \ line continuations.

For a laptop-only backup, LAN access is enough. A public tunnel is optional. A persistent Docker host can coexist with Pocket Nodes and a Cloudflare edge as independent replicas of the same Guild.

4. Verify it

curl http://127.0.0.1:8787/api/federation/health

When the local host reports healthy, return to Guild setup and mark it as paired. A later pairing pass can replace this acknowledgement with cryptographic reconstruction proofs.

5. Optional: give the Guild its own Cloudflare doorway

Only do this if you want an always-online public edge. Authenticate Wrangler to the Cloudflare account that should own this Guild, then choose a Guild ID:

npx wrangler login
node scripts/setup-cloudflare-node.mjs --host-id <guild-id>

That setup creates civweave-<guild-id>.pages.dev, the civweave-host-edge Worker, and three starter Durable Object nodes in the authenticated Cloudflare account. Nothing is created in the download source Guild's account.

6. Connect Guildkeeper payouts

Open the local operator console, unlock its controls with this host's internal credential, and choose Connect payouts. Stripe-hosted onboarding collects the Guildkeeper's identity, tax, bank, and payout details; Civweave stores only the connected-account identifier and readiness status.

Open operator payout setup

A created Stripe account is not enough: Guildkeeper revenue stays disabled until Stripe reports the connected account's transfer capability as active.
